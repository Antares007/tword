In the Beginning Was the Step: Typed Semantics

Before the Word

Before the word, there was the wire.

Before the language, there was the circuit.

Before the abstraction, there was the substrate — running, stepping, transitioning, enforcing — with zero overhead, because it was the ground and not an implementation on top of the ground.

We arrived late. We named what was already happening. We called it computation.

And then we made a mistake that has cost us fifty years: we defined computation by its description rather than by its substance. We built languages to talk about steps instead of building steps themselves. We wrote programs that described what should happen instead of being what should happen.

The gap between description and substance is where every bug lives.

The step is the way to close it.

What a Step Is

A step is the smallest unit of computation that carries its own meaning forward.

A function that returns a value is a description of a transformation. It takes input, produces output, and terminates. The continuation — what happens next — lives outside the function, in the caller, in the stack, in the implicit protocol of the execution model.

A step carries the continuation inside its type. It does not terminate. It hands control forward to the next typed machine. The "what happens next" is explicit, typed, and enforced at compile time.

The difference is the difference between a message and a wire.

A message describes what should flow. A wire enforces what can flow. Physics builds with wires. We built with messages. And every message that arrives at the wrong receiver, with the wrong type, at the wrong time, is a bug.

The step is the wire. The type is the wire. The circuit is the program.

The Substrate Speaks First

Physics is the original type system.

A floating-point register cannot receive an integer instruction. This is not a rule. There is no documentation to read, no convention to follow, no discipline to maintain. The circuit will not allow it. The type is the wire, and the wire is physics.

Hardware operational semantics are specified by construction. The CPU does not approximate its behavior. It instantiates it. Specification and realization are the same act. The CPU is its own proof.

This is what zero overhead means. The substrate does not pay the cost of translation between what it says and what it does. There is no translation. The substrate is the behavior.

When we build software, we translate. We write a description, compile it into another description, link it into yet another description, and finally load it into a substrate that has been running all along, waiting for us to catch up.

Every layer of translation is overhead. Every layer of translation is a gap where the description can diverge from the substrate. Every divergence is a potential bug.

The direction of growth is from the substrate upward. Grow the semantics. Close the gap. The perfect program is physics — not because we will reach it, but because it is the direction.

Four Types, One Circuit

The Turing machine is the proof of concept.

typedef struct ξ ξ;
typedef struct ρ ρ;
typedef struct ω ω;
typedef struct δ δ;
struct ρ { void (*step)(ω, char, ω); };  // read:  receives left writer, symbol, right writer
struct ξ { void (*step)(ρ);          };  // cell:  offers itself to an observer
struct ω { void (*step)(char, δ);    };  // write: receives symbol and move direction
struct δ { void (*step)(ξ);          };  // move:  receives next cell

Four types. Four roles. The entire computational substrate of a universal machine specified in sixteen lines of C.

Read the types as a circuit diagram:

ξ → ρ → ω → δ → ξ

The cell offers itself to be read. The observer reads the cell, receives the current symbol and two continuations — left and right. The writer receives a new symbol and a direction. The mover receives the next cell and the cycle begins again.

Every valid transition is explicit in the type. The circuit has no implicit "what happens next." The return address does not exist. The stack to corrupt does not exist. The untyped continuation that ROP exploits does not exist.

The assembly confirms it:

c9l:
    mov byte ptr [rip + c9], di
    lea rdi, [rip + c0p]
    jmp rsi

c0p:
    mov rax, rdi
    movsx esi, byte ptr [rip + c0]
    lea rdi, [rip + c0l]
    lea rdx, [rip + c0r]
    jmp rax

Every function ends in jmp. The compiler eliminated every stack frame because there was nothing to return to. The typed steps are the control flow. The control flow is the type. The type is the wire.

This is what typed semantics looks like when it reaches the substrate.

The Observer and the Locus

The cell ξ is more than a memory location. It is a typed ambiguous step.

When the observer ρ reads the cell, it receives the current symbol and two possible continuations — left and right. The cell does not tell the observer what to do. The cell offers what is admissible. The observer chooses based on its own state.

The cell is the state locus: the point in the circuit where multiple continuations are possible, where the machine carries ambiguity forward rather than resolving it prematurely.

This is the foundational insight of typed semantics: ambiguity is structure.

A function that returns a value resolves ambiguity by collapsing it. There is one return value. The caller decides what to do with it. The decision is made outside the typed system, in code that the type system cannot reason about.

A typed step preserves ambiguity in the type. The state locus carries multiple possible continuations. Each continuation is typed. Each is admissible. The choice is made by the next typed machine, inside the typed system, where the type system can reason about it.

The circuit is richer for the ambiguity. The type system is stronger for encoding it.

Yin, Yang, and the Geometry of Composition

Ambiguity composes.

Two abstract ambiguous steps — call them Yin and Yang:

Yin defines admissible continuations and selects one defined by Yang. Yang's chosen continuation defines its admissible continuations and chooses one defined by Yin.

This is not a metaphor for balance. This is a formal description of how two machines negotiate a shared computation. Each machine constrains the other's choice space. Each machine's output is the other machine's input. The computation lives in the dialogue between them.

Samson Abramsky and Radha Jagadeesan formalized this structure in game semantics: computation as a game between Opponent and Proponent. Opponent defines the admissible moves. Proponent responds. The response constrains the next round of admissible moves. The game is the computation.

We arrived at the same structure from hardware intuition, from typed steps, from the circuit diagram. Different path, same ground.

The Yin/Yang composition is not a special case. It is the general pattern. Any two typed machines can be composed this way. The composition is typed. The interface is enforced. The circuit grows.

We can invite other roles into the composition. Grammar defines what sequences are admissible. Traversal defines how to walk them. Actions define what to do at each node. Three separate typed machines, each evolving in its own layer, each composable with the others by typed interface.

The parser is not a monolithic control flow graph. The parser is three machines plugged together. Change the traversal and the grammar remains. Change the grammar and the actions remain. Each machine grows independently. Each interface is preserved.

Operational Semantics as Growth

Operational semantics is the language.

The source language is given in the beginning — by physics, by the hardware, by the instruction set. The task of programming is to grow new operational semantics within that source language: new words, new machines, new substrates.

The transistor is the primary word. The gate is a grown word. The register is a grown word. The instruction set is a grown grammar. The compiler is a grown traversal. The language is a grown interface.

Each layer grows within the substrate of the layer beneath it. Each layer is complete before the next layer begins. Each layer enforces its invariants by construction.

The return-value-oriented composition paradigm breaks this chain. When we build operational semantics on top of a return-based execution model, we import the implicit assumptions of that model into every layer above it. The call stack becomes invisible infrastructure. The return address becomes an untyped global. The execution model becomes the substrate, and the substrate is borrowed, undocumented, and untyped at its boundaries.

Typed steps restore the chain. Each typed machine is a complete substrate. Each typed interface is a complete specification. Each typed composition is a complete proof that the interface is satisfied.

Grow the substrate. Type the circuit. The direction is from bottom up.

The Universal Interface

A CPU has pins. The pins are the typed interface. Any board with a compatible socket can receive the CPU. The interface is physical, typed, and universal. No source code is required to use it. The interface is the contract. The contract is enforced by construction.

Software carries a different tradition: the function signature as interface, the call convention as protocol, the documentation as contract. The contract is advisory. Compliance is voluntary. Enforcement is the programmer's discipline.

Typed steps give software what hardware has always had.

Each typed machine lays out in binary as a structured type. The layout is predictable. The layout is hashable. The hash is the handshake between the binary and the type:

ωξω, ωξω, ωξω, ωξω, ... ωξω

That is a crystallized, hashable form of a 10-cell circular tape machine. Index into it and we have a universal interface. Compose it with another typed machine and the interfaces compose. The hash of richer operational semantics preserves the universal interface all the way down.

Root of trust at the substrate. Crown of complexity at the top. One unbroken chain.

The hash is the proof that the tower stands on the ground and not on air.

What Language Is

Language is grown operational semantics.

Every natural language is a set of typed steps grown by a community over millennia, constrained by the physics of sound and meaning, enforced by the circuit of shared understanding. A word that means nothing to its receiver is a type error. A sentence that admits no valid continuation is a dead end.

Every programming language is a set of typed steps grown by a community over decades, constrained by the physics of computation and hardware, enforced by the circuit of compiler and type checker.

The difference between a good language and a poor one is the size of the gap between the language's semantics and the substrate's semantics. A language that maps cleanly to the substrate — that grows from the substrate rather than floating above it — carries less overhead, fewer bugs, and richer composition.

The substrate speaks first. The language grows toward it. The programmer grows the language.

Operational semantics must be imaginable before syntax can be designed. We count sheep before we write numerals. We run circuits before we write programs. The semantics — the act of stepping — precedes the syntax that names it.

The return statement is a syntax that names the wrong semantics. It names termination where there should be continuation. It names collapse where there should be growth.

The typed step names the right semantics. It names the wire, the transition, the circuit, the ground.

The Compiler as Grower

A compiler today takes a description and produces a binary. The type information dissolves at the boundary. The binary carries no typed interface. It is an executable blob that trusts its caller to know what it expects.

A compiler that understands typed steps grows typed machine binaries. The type is crystallized into the binary layout. The hash is computed. The interface is enforced at the binary boundary, not just at the source boundary.

The compilation pipeline becomes a growth process. Each compiled machine is a typed substrate for the next layer. The type does not dissolve at the boundary. The type is the boundary.

Such a compiler does not translate. It grows. It takes typed steps in the source language and produces typed steps in the machine language. The circuit at the source level and the circuit at the machine level are the same circuit, expressed in different substrates.

This is the compiler we are growing toward. The compiler that closes the gap between the type system and physics. The compiler that makes the tower stand on bedrock.

In the Beginning

In the beginning was the Step.

The substrate was stepping before we arrived. Physics was transitioning, enforcing, composing — with zero overhead, zero translation, zero gap between specification and realization.

We arrived and named it. We called it computation. We called it hardware. We called it software. We drew a line between what runs and what describes what should run.

The line is the problem. The line is the overhead. The line is the gap where bugs live and attacks land.

Typed semantics is the discipline of closing the line. Every typed step is a reduction of the gap. Every typed interface is a proof of local closure. Every typed composition is a step toward the substrate.

Hardware is how far we have grown.

Software is the distance that remains.

And the distance is not fixed. The distance closes with every typed step we take.

The Step is the primitive truth.

The Machine is the boundary that gives the Step meaning.

Composition of Machines is all computation.

In the beginning was the Step, And the Step is still stepping, And it always will be.
